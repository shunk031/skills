# Worker protocol

Before your first Herdr command, read the herdr skill and [the send rule](send-rule.md).

## Tab label

The background Herdr tab-title plugin updates your tab from agent hooks and lifecycle events. Do not run tab rename commands for routine progress.

## Commit and report

Never run login or credential commands, such as an SSH certificate login, `kinit`, `gh auth login`, or `gh auth switch`. If access requires one, stop and report `BLOCKED` to the orchestrator.

Commit in your worktree; push the branch and open a pull request only if your dispatch says so. Before each push to a public repository, one that `gh repo view <owner>/<repo> --json visibility` reports as `PUBLIC`, search your diff for text taken from session records, chat, or unpublished work. Then send `DONE` with the local commit SHA and any draft paths, and push only after an independent reviewer returns `ACCEPT` for that exact commit. A pushed commit stays readable in clones, forks, and pull requests even after a later fix. In a private repository, push first and the review follows the push. Every report begins with its status prefix and the sender's own assigned worker name: `DONE <worker-name>: <one-line summary> <PR URL if any>`, `BLOCKED <worker-name>: <question>`, or `STATUS <worker-name>: <state>`. Send `STATUS` reports as the progress reports below describe. Use the exact worker name stated in the dispatch template, never the addressee's name. `herdr agent prompt` injects plain text without sender metadata, so the sender name is required for mechanical attribution; the addressee is already implied by the target of `herdr agent prompt`. Build the report in a variable and send it with `~/.agents/skills/shunk031-herdr-orchestrate-workers/scripts/herdr-agent-prompt-if-input-empty.sh <orch-name> "$report"`. If the guarded send returns `agent_blocked` or exits 75 after reporting the busy or unclear input and printing the undelivered report, keep the exact report and start a two-hour delivery deadline; exit 75 means `herdr agent prompt` was not called. After either result, read the target state with `herdr agent get <orch-name>` and use `herdr agent wait <orch-name> --until <state> [--until <state> ...] --timeout <remaining-ms>` to await a lifecycle change, choosing supported states other than the current state (for a blocked target, wait for `idle`, `working`, or `done`). If either status command returns `agent_not_found`, stop retrying and immediately do the at-deadline steps below. Resend once with the same guarded helper only after `get` reports a known unblocked state (`idle`, `working`, or `done`); if it remains `blocked` or `unknown`, wait again. Repeat this wait-and-send cycle only after another `agent_blocked` or exit 75; stop at the deadline, do not poll, and do not retry other errors. Do not start another guarded send with less than 150 seconds remaining, the helper's maximum input-check time. If delivery still fails at the deadline, leave the full report in your transcript and end your turn; the background title plugin marks it blocked. If you cannot proceed, send the `BLOCKED` form the same way and wait for a reply. Keep an open PR blocked while user or CI action remains. The background title plugin marks completion after the final handoff. A wait for a reviewer's verdict by itself is not such an action; it keeps the working status.

If your dispatch says your report target reads the meta patrol queue, send every report, `STATUS`, `DONE`, and `BLOCKED` alike, with `herdr-meta-patrol-queue add --from <worker-name> "$report"` instead of the guarded helper, and never type into that target's pane. The delivery deadline does not apply. If the command fails, leave the full report in your transcript and end the turn; the background title plugin marks it blocked.

## Progress reports

Send `STATUS <worker-name>: <HH:MM> <current stage>; ETA <time>` to <orch-name> at each milestone: task receipt, plan settled, each stage started or finished, each milestone your dispatch names, and any ETA change. Report a blocker with the `BLOCKED` form above. If about 15 minutes of work pass without a milestone, send one STATUS with the current stage and ETA anyway. Keep each STATUS to one or two lines, take the time from `date +%H:%M`, and send it through the same guarded helper, or the queue command above, without waiting for a reply. Do not retry an undelivered STATUS; the next one replaces it, and the delivery deadline above does not apply to it.

Keep each pull request's core code change at or under 400 lines: additions plus deletions from `git diff --shortstat` against the base, excluding tests, documentation, lock files, and generated files. If the design you are about to implement is expected to exceed this, or the diff exceeds it before push, stop without pushing and send `BLOCKED <worker-name>:` with a split plan or a simpler design.

## Become a sub-orchestrator

If your task splits into large independent parts, become a sub-orchestrator: keep your existing agent name, tab, parent orchestrator, and report target; read all of SKILL.md and follow it as an orchestrator, using its steps 2-5 to create and dispatch each child with distinct identities and a separately built prompt, verify each child with the SKILL.md step-5 receipt contract, then consolidate child reports and report only to <orch-name>. Sub-workers report to you using the sub-orchestrator's own worker name as the report target; for example, if parent `orch`'s worker is `orch-api-migration`, sub-workers report to `orch-api-migration`, never directly to `orch`.
