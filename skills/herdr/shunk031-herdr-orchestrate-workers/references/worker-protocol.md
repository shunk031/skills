# Worker protocol

## Tab label

Keep your own tab label according to the `shunk031-herdr-tab-status` skill; it owns live tab lookup, rename commands, and response verification. Do not duplicate its status syntax here.

## Commit and report

Commit in your worktree; push the branch and open a pull request only if your dispatch says so. Every report begins with its status prefix and the sender's own assigned worker name: `DONE <worker-name>: <one-line summary> <PR URL if any>`, `BLOCKED <worker-name>: <question>`, or `STATUS <worker-name>: <state>`. Use the exact worker name stated in the dispatch template, never the addressee's name. `herdr agent prompt` injects plain text without sender metadata, so the sender name is required for mechanical attribution; the addressee is already implied by the target of `herdr agent prompt`. Build the report in a variable and send it with `~/.agents/skills/shunk031-herdr-orchestrate-workers/scripts/herdr-agent-prompt-if-input-empty.sh <orch-name> "$report"`. If the guarded send returns `agent_blocked` or exits 75 after reporting the busy or unclear input and printing the undelivered report, keep the exact report and start a two-hour delivery deadline; exit 75 means `herdr agent prompt` was not called. After either result, read the target state with `herdr agent get <orch-name>` and use `herdr agent wait <orch-name> --until <state> [--until <state> ...] --timeout <remaining-ms>` to await a lifecycle change, choosing supported states other than the current state (for a blocked target, wait for `idle`, `working`, or `done`). If either status command returns `agent_not_found`, stop retrying and immediately do the at-deadline steps below. Resend once with the same guarded helper only after `get` reports a known unblocked state (`idle`, `working`, or `done`); if it remains `blocked` or `unknown`, wait again. Repeat this wait-and-send cycle only after another `agent_blocked` or exit 75; stop at the deadline, do not poll, and do not retry other errors. Do not start another guarded send with less than 150 seconds remaining, the helper's maximum input-check time. If delivery still fails at the deadline, leave the full report in your transcript, use the blocked status defined by `shunk031-herdr-tab-status`, then end your turn. If you cannot proceed, send the `BLOCKED` form the same way and wait for a reply. Keep an open PR in the user-action handoff status defined by `shunk031-herdr-tab-status` until no user or CI action remains; only then use its completion status.

Keep each pull request's core code change at or under 400 lines: additions plus deletions from `git diff --shortstat` against the base, excluding tests, documentation, lock files, and generated files. If the design you are about to implement is expected to exceed this, or the diff exceeds it before push, stop without pushing and send `BLOCKED <worker-name>:` with a split plan or a simpler design.

## Become a sub-orchestrator

If your task splits into large independent parts, become a sub-orchestrator: keep your existing agent name, tab, parent orchestrator, and report target; use SKILL.md steps 2-5 to create and dispatch each child with distinct identities and a separately built prompt, verify each child with the SKILL.md step-5 receipt contract, then consolidate child reports and report only to <orch-name>. Sub-workers report to you using the sub-orchestrator's own worker name as the report target; for example, if parent `orch`'s worker is `orch-api-migration`, sub-workers report to `orch-api-migration`, never directly to `orch`.
