# 技術スライドのテレグラフ文体

## 大原則

- この skill は `shunk031-writing-kosshi` skill に依存するため、最初に同 skill を読み、主張と根拠の骨子を作る
  - 論点の階層、事実保持、引用、不足情報の扱いは同 skill に委ねる
  - この skill は、骨子を技術・論文紹介スライドに分け、各スライドに載る長さまで文章を短くする
- この skill はスライドに載せる文章と構成を扱う
  - 配色、レイアウト、図版選定、アニメーション実装、PPTX や PDF の生成は対象外

## スライド全体の構成

- スライド全体は、聞き手が内容を追う順に組み替える
  - 論文紹介では、表紙・自己紹介の後に `本論文の選定理由` を置き、発表者が何に注目したかを先に示してよい
  - 本編は、導入・関連研究・手法・実験設定・結果・議論と制限・今後の展望・まとめなどから、内容に必要な節だけを選ぶ
  - サーベイでは、全体像や分類軸を先に示し、分類ごとの説明、節ごとのまとめ、未解決課題、今後の方向性へ進める
  - 論文の章順を写すのではなく、選定理由で示した問いに答える流れを優先する

## 一枚の構成

- 一枚では一つの内容を説明し、タイトルで全体のどの節にいるかと、そのスライドで扱う対象を示す
  - スライドタイトルは `<節> | <そのスライドで扱う対象>` を基本とし、短いラベルには `:` も使える
  - 一つの対象を複数枚で見せる場合は `<節> 1/N | <対象>` や `<節> | <対象> 1/N` のように連番を付ける
  - 同じスライドを段階的に表示するときは、本文を保ったまま図や注釈だけを追加することがあるため、同じ本文を別の論点として数えない
  - 枚数が多い場合は、全体の分類や現在の節を繰り返し示し、節の切り替わりでまとめを置いてよい
- 各スライドは、結論を一文だけ置く形式に固定せず、必要な項目を組み合わせる
  - タイトルの下に、`主要な結果`、`結果の解釈`、`現状と課題`、`将来方向` など、そのスライドに必要な短い小見出しを置く
  - 各項目は、小見出しの下に主張・分類・手順を置き、その下に根拠・条件・詳しい説明を置き、必要なら定義や例をさらに加える
  - 箇条書き記号の種類は文体の要件にせず、インデントで階層を示す
  - 説明の結論を示す必要があるスライドだけ、`➜`、`示唆`、`結果の解釈`、`本研究領域の要点` などで結論を示す
  - タイトル、小見出し、結論だけを拾っても、スライド全体の流れが追えるか確認する

## 事実と出典

- 論文が述べた事実と発表者の解釈を区別する
  - 素材にある発表者の補足、解釈、疑問は `本資料では`、`結果の解釈`、`気になったところ`、疑問形などで見分けられるようにする
  - 選定理由や余白の注釈では口語や感情表現も使えるが、論文中の事実を説明する箇所には混ぜない
- 出典を引用対象の近くに置くという `shunk031-writing-kosshi` skill の規則を、スライドでは引用対象の直後に短い角括弧書式で表す
  - 基本形は `手法名 [第一著者+ 会議・媒体’YY]` とし、素材に会議・媒体がなければ補わない
  - 一つの文に複数の手法があれば各手法の直後へ個別に付け、一つの主張を複数文献が支える場合だけ同じ角括弧内にまとめる
  - 図版の引用は `From [第一著者+ 会議・媒体’YY]` や `図は [第一著者+ 会議・媒体’YY] より引用` として図の近くに置く
  - 引用を文末やスライド末尾へまとめて移さない

## 文体と記号

- 各行は、一読で意味が取れるテレグラフ文体へ短くする
  - 文脈から分かる主語や助詞と、文末の `である`、`です` を省き、名詞だけの行と短い文を自然に混ぜる
  - 一行で扱う内容は一つに絞る
  - 専門語は初出時に日本語と英語名・略称を対応させ、以降は略称を使う
  - タイトルと小見出しも、箇条書きと同じく行末に句点 `。` を付けない
- 記号は、語句間の関係を短く示せる場合だけ使う
  - `➜` は直前の内容を受けて、前提から帰結、問題から次の焦点、比較から解釈へ進む箇所に置く
  - `vs.` は対比、`:` はラベルと内容、`/` は並列・併記、`|` は節名とそのスライドの題目の区切りに使う
  - `👍`、`🤔` などは発表者の評価を明示する場合だけ使い、装飾目的では使わない
  - 記号だけで関係が曖昧になる場合は、短い日本語で書く

## 保守

どちらかの skill を変更するときは両方を読み、共通規則を `shunk031-writing-kosshi` skill に集約し、重複や矛盾を同じ変更で解消する。

## 入出力例

以下は架空の手法と文献を使った例である。

入力:

```markdown
検索候補の再ランキング手法を紹介する。QueryRank は推論時に検索結果を再評価する手法で、Yamada らが ACL 2025 で発表した。CacheSort は索引作成時に候補を圧縮する手法で、Smith らが SIGIR 2024 で発表した。同じ評価条件で、NDCG は QueryRank が 0.412、CacheSort が 0.398、ベースラインが 0.374 だった。QueryRank は推論レイテンシが 18%増えた。発表者は、精度向上とレイテンシ増加の釣り合いを追加検証したいと考えている。Yamada らの Figure 2 を使用する。
```

出力:

```markdown

- QueryRank [Yamada+ ACL’25]

## 実験結果 | 精度向上とレイテンシの増加

同一条件での NDCG

- QueryRank: 0.412
- CacheSort: 0.398
- ベースライン: 0.374

計算コスト

- QueryRank の推論レイテンシ: +18%

➜ QueryRank は精度で優位・推論コストとの釣り合いは未検証

気になったところ

Figure from [Yamada+ ACL’25]
```
