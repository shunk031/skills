# Verify local prose

Try to refute the prose after the global structure is settled. Flag unclear sentence order, broken transitions, inconsistent terms, undefined technical language, mechanical errors, AI-tell phrasing, and explanations or prompt residue that only the originating conversation supports. Quote the smallest evidence that identifies each finding.

Check evidence by kind. Published works need a footnote marker attached directly to the named entity and a definition with authors or organization, title, venue, year, and a DOI, arXiv, or ACL URL; resources such as repositories, code or data files, documentation, dataset cards, and licenses need descriptive inline links. Within a paragraph, table row, or contiguous list, mark each entity once at most, share one marker across sibling entities, ensure every cited entity has a marker somewhere, and reject a duplicate `Paper:` entry for a work already marked in that passage. Re-mark a cited entity in a distant load-bearing section with the same number when needed. Turn bare in-repository file-path mentions into relative links, and accept only repo-relative or commit-pinned in-repository links, never branch-qualified ones.

Check that abbreviations are expanded at first use unless they are universally understood tokens such as URL, JSON, HTTP, PDF, API, CLI, README, and DOI, or proper names and brands such as JSTOR, arXiv, and GitHub. Check that sentence subjects are explicit when pronouns would be ambiguous, uncertainty uses plain-language hedges, durable caveats state their scope or condition, and evaluative claims name their criterion or use a hedge. Omit needless volatile external facts, and anchor load-bearing volatile facts to repository artifacts or pinned snapshots. Reject self-assessed artifact size or effort qualifiers such as "small", "thin", "simple", or "lightweight". Check that fragment bullets omit periods, sentence bullets use punctuation, and each list follows one convention.

Specimen: "sentence structure and grammar."
